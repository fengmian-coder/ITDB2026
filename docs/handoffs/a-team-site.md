## 当前行为与验收范围

首页沿用个人作业 2 的深绿导航、球场背景、球队搜索与纪念卡区块。球队数量、比赛数量读取数据库；纪念卡区域按用户要求固定展示个人作业 2 的卡片示例，正式制作页仍读取数据库。球场背景复用个人作业素材 `pascal-muller-0oMsWA8yLN0-unsplash.jpg`；它只是球场氛围图，不标为 2026 世界杯实拍。原素材及设计截图留在个人作业目录。

团队和成员可在后台新增、编辑、删除；前台按显示顺序读取。成员初始化资料存放于 `data/project-members.json`，已按用户提供的个人作业 3 截图更新为：A 卢苑、B 胡乐妍、C 袁颢心、D 张馨月，以及截图中的负责方向和分工。已有本地成员也已原位更新，成员 ID 与作业归属保留。团队名称仍可由小组在后台调整。

管理员可以上传、替换、修改归属、删除课程文件。文件存放在 Web 根之外的 `data/team` 或 `data/personal`，随机命名；原文件名存在数据库中，用于附件下载。变更作业类别时，文件同步转存到对应目录。个人作业必须属于所选团队中的成员；团队作业不绑定成员。已有关联成员或作业的团队、已关联个人作业的成员不能删除。

纪念卡通过 B 的 `JourneyService` 读取候选比赛，通过 `MatchQueryService` 读取比赛详情、最终场上比分、点球和已发布故事。感想、可选照片、Canvas 绘制与 PNG 导出均在当前浏览器中处理，不提交到服务器、不建普通用户账号、不创建纪念卡数据库表。照片支持 JPG/PNG/WebP，最大 5 MB。

## 文件与路由

| 路由 | 用途 | 主要代码 |
|---|---|---|
| `site/index` | 数据库驱动首页 | `SiteController`、`views/site/index.php` |
| `site/explore?q=` | 球队名称入口 | `TeamDirectoryService`、`views/site/explore.php` |
| `project-team/index` | 团队、成员公开介绍 | `ProjectTeamController`、`ProjectTeam`、`ProjectMember` |
| `admin-project/index` / `view?id=` | 团队管理 | `AdminProjectController`、`views/admin-project` |
| `admin-project/create` / `update?id=` / `delete?id=` | 团队维护 | 同上 |
| `admin-project/create-member?team_id=` / `update-member?id=` / `delete-member?id=` | 成员维护 | 同上 |
| `document/index` / `download?id=` | 作业目录和受控下载 | `DocumentController`、`ProjectDocument`、`DocumentStorageService` |
| `admin-document/index` / `create` / `update?id=` / `delete?id=` | 作业文件管理 | `AdminDocumentController`、`views/admin-document` |
| `memory/card?team_id=&match_id=` | 无注册纪念卡 | `MemoryController`、`MemoryCardService`、`memory-card.js` |

后台使用 D 的 `AdminUser::canManage` 与既有管理员会话。读取只允许 GET/HEAD；保存使用 POST；删除仅允许 POST、有效 CSRF 和显式勾选确认。`id`、时间戳、存储路径和文件大小均不接受客户端直接写入。

`TeamDirectoryService` 只读 C 的球队名称、英文名、FIFA 代码与本届参赛关系，不实现 C 的 Model 或统计公式。C 的 `NationalTeamController` 交付后，`site/explore` 自动转到约定的 `national-team/index?q=`。C 的 `TeamStatsService` 存在时，纪念卡数据服务会调用其 `getTeamStats()`；不存在时不编造统计值。当前图片版面没有展示球队累计统计，后续有需要时再使用返回值。

## 初始化与恢复

先按主 README 安装依赖，在全新空数据库中执行 C 的 `data/install.sql`，配置被 Git 忽略的 `config/db.local.php`。不要在已有表的库上重复执行建表脚本。

```powershell
composer install
php yii project/init
```

`project/init` 在团队表非空时跳过，保留已有资料。当前资料包包括 A 的三份个人作业报告、个人作业 1 源码包、个人作业 2 Axure RP 和团队 V1.1 协作规范，共六份文件；协作规范不代表六项团队课程交付文档已经全部完成。

查看后台或数据库中的团队 ID 与成员 A 的 ID，再登记随仓库分发的文件。下面的 1、1 只适用于刚初始化的空库，不能在已有库里盲用：

```powershell
php yii project/register-bundle 1 1
```

该命令依据 `data/a-documents-manifest.json` 校验 SHA-256、文件大小及受控目录，事务性登记元数据；已有相对路径的记录跳过，不覆盖已有资料。路径、文件名均与数据库自增 ID 无关。另可导入本机新文件，原文件只复制：

```powershell
php yii project/import '完整文件路径' '作业标题' <团队ID> [成员ID]
```

省略成员 ID 表示团队资料。新增其他成员的作业也可以直接使用后台上传。文件限制为 20 MB；部署时 PHP 的 `upload_max_filesize` 至少设为 `20M`，`post_max_size` 至少设为 `24M`。以仓库内实际白名单为准，不支持 PHP、HTML、JS 等脚本文件。

管理员继续由 D 的命令创建，不在 SQL、文档或 Git 中预置账号密码：

```powershell
php yii admin/create <管理员账号>
php yii serve 127.0.0.1 --port=8080
```

本次电脑上的本地便捷脚本是 `runtime/start-dev.cmd`、`runtime/yii.cmd`、`runtime/composer.cmd`，只适用于当前工具安装位置，不随 Git 分发。本地管理员密码说明位于 `runtime/admin-login.txt`，不要提交。
