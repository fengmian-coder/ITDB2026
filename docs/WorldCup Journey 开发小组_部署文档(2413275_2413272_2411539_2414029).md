## 1. 部署方式

本项目提供 **Windows 本地脚本式一键部署**和 **macOS 终端部署**。Windows 用户运行 `scripts/start.ps1`，即可依次完成应用依赖安装、数据库结构与初始数据还原、管理员初始化及网站启动。首次运行需要输入本机 MySQL 连接信息，后续运行复用已保存的配置。macOS 用户配置本机数据库连接后，使用相同的 Yii 命令还原数据和启动网站。

应用采用 Yii 2.0 Advanced 多应用结构，前台、后台和控制台各有配置及入口，使用同一个 MySQL 项目库。脚本通过 PHP 内置服务器提供本机访问，绑定 `127.0.0.1`，以 `web/` 为网站公开目录。该兼容入口按路由启动前台或后台应用，沿用原有访问地址，适用于课程验收和本机演示。

## 2. 用户设备的准备工作

| 项目 | 要求 |
| --- | --- |
| 操作系统与终端 | Windows 11 使用 PowerShell 5.1 或更新版本。macOS 使用终端（zsh 或 bash） |
| PHP | 8.2.x。启用 `pdo_mysql`、`mbstring`、`openssl`、`intl`、`curl`、`zip`、`gd`、`fileinfo` |
| Composer | 2.x，与 PHP 8.2 配合使用。首次安装依赖需要网络 |
| MySQL | 8.0.16 或更高的 8.0 版本，服务已启动。账号应能在项目库中建表并读写数据。由脚本新建数据库时，账号还需具备建库权限 |
| 本地目录 | 使用当前用户可写的文件夹。项目运行会写入 `vendor/`、`runtime/`、`web/assets/` 和本地配置 |
| 项目源码 | 获取课程提交的完整源码包，或使用 Git 克隆仓库 `main` 分支。完整保留 `composer.lock`、`data/` 和 `scripts/` |

在新设备上先安装上述工具并启动 MySQL 服务，再打开 PowerShell 或 macOS 终端检查版本和扩展。设备装有多套 PHP 时，Windows 可用 `Get-Command php` 查看执行路径，macOS 可用 `command -v php`。

```powershell
php -v
php --ini
php -m
composer --version
```

如果需要测试 MySQL 账号，先确认命令行能找到 MySQL 客户端（Windows 上为 `mysql.exe`，macOS 上为 `mysql`）。将下列命令中的占位用户名替换为本机账号，按提示输入密码。连接成功后输入 `exit` 退出。

```text
mysql -h 127.0.0.1 -P 3306 -u YOUR_MYSQL_USER -p
```

## 3. 在自己的电脑上部署

### 3.1 获取代码

使用源码包时，解压后在终端中进入包含 `composer.json` 和 `scripts/` 的目录。使用 Git 时，可以在 PowerShell 或 macOS 终端执行以下命令。

```text
git clone --branch main https://github.com/fengmian-coder/ITDB2026.git
cd ITDB2026
```

### 3.2 Windows 一键部署

确认 MySQL 已运行，在项目根目录执行。

```powershell
.\scripts\start.ps1
```

| 首次运行提示 | 填写方式 |
| --- | --- |
| MySQL host | 数据库与网站在同一台电脑时可回车接受 `127.0.0.1` |
| MySQL port | 使用默认 MySQL 端口时可回车接受 `3306` |
| Database name | 可回车使用项目专用库 `worldcup_journey`，也可填写为项目单独准备的库名 |
| MySQL username | 填写本机有项目库权限的 MySQL 账号 |
| MySQL password | 输入该账号的密码。终端以隐藏方式读取 |

若 `php` 或 `composer` 未加入 PATH，使用实际安装路径。下例中的目录仅作示例。

```powershell
.\scripts\start.ps1 -Php 'C:\devtools\php-8.2\php.exe' -Composer 'C:\devtools\composer\composer.bat'
```

### 3.3 Windows 访问网站与后台

1. 等待终端显示 `Database preparation complete.` 和 `Ready at`。将 `Ready at` 后面的地址复制到浏览器。默认是 `http://127.0.0.1:8080/`，实际端口以终端为准。
2. 首页打开后，从顶部导航进入「球队」「比赛」或「数据总览」检查内容。
3. 点击「管理员登录」。新库首次启动且管理员表为空时，脚本创建 `wcj_admin`，并在终端显示一次随机密码。已有管理员记录时使用该环境的原账号。
4. 运行期间保留 PowerShell 窗口。演示完成后在对应终端按 `Ctrl+C` 停止服务。下次从项目根目录运行同一命令即可重新启动。

### 3.4 macOS 终端部署

在 Mac 上按第 2 节准备 PHP 8.2.x、Composer 2 和 MySQL 8.0，确认 MySQL 服务已启动。按第 3.1 节获取源码，从终端进入项目根目录。

**第一步　安装依赖并生成本地配置**

```bash
composer install
composer check-platform-reqs
php yii bootstrap --interactive=0
```

**第二步　填写本机 MySQL 连接**

打开项目中的 `config/db.local.php`，按本机环境填写 `dsn`、`username` 和 `password`。默认 DSN 为 `mysql:host=127.0.0.1;port=3306;dbname=worldcup_journey`。如果使用了不同的端口或项目库名，在 DSN 中一并调整。可用有建库权限的账号让脚本创建项目库，也可使用预先建立、已授权的空项目库。

**第三步　还原数据库并启动网站**

```bash
YII_ENV=prod php yii deploy/prepare --interactive=0
YII_ENV=prod php yii serve 127.0.0.1 --port=8080
```

先等待还原命令成功，再执行启动命令。还原会建表、导入赛事数据、初始化团队并登记交付包内的课程资料。管理员表为空时，终端会显示 `wcj_admin` 的随机密码。

浏览器打开 `http://127.0.0.1:8080/`，可从顶部「管理员登录」进入后台。若端口被占用，将 `--port=8080` 改为可用端口，并打开对应地址。按 `Ctrl+C` 停止服务。依赖、配置和数据库已准备好时，日常运行可直接执行启动命令。

macOS 流程已对照项目代码核对。实机部署验收记录来自 Windows 环境。

## 4. 自动部署和数据还原流程

| 顺序 | 脚本操作 | 还原结果 |
| --- | --- | --- |
| 1 | 检查 PHP 版本和扩展、Composer 版本、可用 Web 端口 | 确认运行条件，默认在 8080 至 8100 中选择可用端口 |
| 2 | 读取或生成本地连接配置，按 `composer.lock` 安装依赖并检查平台要求 | 生成或复用 `config/db.local.php`，将依赖安装到 `vendor/` |
| 3 | 执行 Yii 初始化与 `deploy/prepare` | 准备本地 Cookie 密钥，使用 `data/install.sql` 建立 15 张业务表。目标库不存在时尝试创建 |
| 4 | 从 `data/import/` 导入赛事包，补充球队档案基础数据 | 新库还原 2026 届赛事、48 支球队及参赛关系、16 座场馆、104 场比赛，以及 8 篇已发布精选故事及其事件和标签 |
| 5 | 初始化团队和成员，按交付版本内置的清单登记课程附件 | 空库首次还原会登记 13 份课程附件，包括 1 份团队资料和 4 名成员各自的 3 份个人作业。个人作业显示在所属成员页面 |
| 6 | 检查管理员记录并启动 PHP 本地服务 | 管理员可登录后台，浏览器可通过终端显示的地址访问网站 |

`config/db.local.php` 与 `config/params-local.php` 分别保存本机数据库连接配置和 Cookie 密钥，均由各设备独立配置。赛事 CSV、课程附件及其登记清单随源码交付。

### 5.2 Advanced 独立入口

课程本机演示使用同一个地址。需要将前台和后台分别部署时，使用 `frontend/web/` 与 `backend/web/` 作为各自的文档根目录。两个应用通过共同的数据库配置读写同一项目库。为两个应用设置以下环境变量，并按第 4 节先完成一次数据库还原。

| 变量 | 值 |
| --- | --- |
| `WCJ_FRONTEND_ENTRY` | 前台完整入口 URL，包含 `/index.php` |
| `WCJ_BACKEND_ENTRY` | 后台完整入口 URL，包含 `/index.php` |
| `WCJ_ASSET_URL` | 共用静态资源的 URL 前缀，例如在两个站点上分别将 `/shared` 映射到项目 `web/` 的静态资源 |

静态资源映射应由 Web 服务器按静态文件提供，附件下载继续走应用路由。独立部署时分别打开首页与后台登录页，检查跨站链接、静态资源加载以及未登录访问后台时的跳转。

## 6. 重复部署与常见问题

| 现象 | 处理方式 |
| --- | --- |
| PowerShell 找不到 `php` 或 `composer` | 使用前述 `-Php` 和 `-Composer` 参数指定绝对路径，或配置 PATH 后重新打开终端 |
| PHP 版本不符或扩展缺失 | 使用 `php --ini` 确认正在加载的配置文件，启用缺失扩展。重新执行 `php -v` 和 `php -m` 确认 |
| MySQL 连接失败或拒绝访问 | 检查服务是否运行、端口、账号及密码。已保存的连接信息位于 `config/db.local.php`，修改后重新运行 |
| 数据库权限不足或结构不兼容 | 检查项目库权限。若目标库中已有其他应用的表或结构不符，使用另一个专用库名重新还原 |
| 端口不可用 | 优先使用脚本自动选出的地址，也可执行 `.\scripts\start.ps1 -Port 8082` 指定可用端口 |
| 页面未显示课程作业 | 确认运行的是完整交付版本，并查看脚本是否提示附件缺失或归属无法匹配。代码中的附件需登记到当前应用使用的数据库后才会显示 |
| 安装或导入中断 | 保留项目库与本地配置，排除终端所示原因后重试。部署和导入错误记录在 `runtime/logs/app.log` |

Windows 用户可先完成还原，稍后再启动网站。

```powershell
.\scripts\start.ps1 -PrepareOnly
.\scripts\start.ps1
```

在另一台设备复现初始交付状态时，使用完整交付包和独立的 MySQL 项目库，再按第 3 节执行。脚本从仓库内容还原初始数据。若要迁移演示期间新增的留言、后台编辑或课程附件，需要同时迁移本机数据库备份与对应的附件文件。
