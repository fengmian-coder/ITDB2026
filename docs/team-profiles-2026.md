# 2026 球队轻量档案初版

成员 A 于 2026-11-12 在现有球队模块上补充人物资料，保留球队、比赛、DNA、PK 和旅程的既有数据服务及路由。

## 内容与来源

`data/team-profiles-2026.json` 覆盖 48 支球队、48 位本届主教练和 144 位代表球员。

唯一基础来源为 [FIFA 2026 官方参赛名单](https://fdp.fifa.org/assetspublic/ce281/pdf/SquadLists-English.pdf)，48 页，2026-07-19 22:34 UTC，Version 1。资料包记录来源 PDF 的 SHA-256，每队记录对应页码链接。人物使用名单中的常用原文姓名，教练国籍翻译为中文；科特迪瓦教练名字的首字母缺失另按 [FIFA 球队名单报道](https://www.fifa.com/en/tournaments/mens/worldcup/canadamexicousa2026/articles/cote-divoire-squad-announcement-emerse-fae) 校正为 Émerse Faé。

每队从后卫、中场、前锋位置各选取名单所列国家队出场数最多的一人，并列时保留名单顺序。这是本项目第一版的介绍选取规则，不是官方最佳阵容、当届最佳球员或完整阵容。姓名及球衣号码、位置、俱乐部、国家队累计出场和进球均按同一版本名单。累计数据不等于本届赛事数据，俱乐部也不表示现在的所属俱乐部。

球队介绍根据名单阵容人数与位置构成整理，教练简短介绍采用本届身份和名单国籍。初版没有添加无法由该来源证明的战术评价、人物传记或执教风格。后续可以通过后台补充经核对的更丰富介绍，同时更新来源与版本。

## 页面与后台

前台按“球队概览 → 简介／教练 → 三位代表球员 → 现有本届统计”排列。基本球队简介 `national_team.description` 仍保留；已有非空内容作为补充介绍显示，不被导入程序覆盖。

后台“球队管理 → 球队详情 → 维护 2026 球队档案”可编辑简介、主教练、三位球员、来源和资料版本。使用现有管理员权限、POST 和 CSRF。校验失败保留表单，所有公开内容以文本编码输出。暂不提供球员独立详情、球员数据库、球员照片或实时转会信息。

## 数据库增量与协作说明

在 `tournament_team` 增加唯一的可空扩展字段 `profile_json JSON NULL`，保存 summary、coach_name、coach_description、players、source_url、source_label、edition。players 为三项数组，每项为 name、position、description、shirt_number。档案以现有 `(tournament_id, team_id)` 关联，当前维护 2026 届快照；不添加独立球员或教练表，仍为 15 表。

本次是 A 获用户授权的功能扩展，字段及 JSON 结构需随 PR 交 C 复核并纳入后续统一基线，不代表 C 已单独审核。`data/install.sql` 同步包含该字段，仅用于新空库。现有库使用以下幂等增量命令，不要重新导入建表脚本：

```powershell
php yii team-profile/prepare
```

该命令先检测字段，再仅在缺失时添加；按 FIFA 代码找到现有 2026 参赛记录，事务登记尚未填写的档案。已有非空档案保留，后台编辑后再次运行不会覆盖。不存在球队或参赛关系时跳过，不创建球队、不修改比赛、分组或最终成绩。资料源校验失败时整批登记回滚；MySQL DDL 增量独立于数据事务。

新电脑 `deploy/prepare` 在现有赛事 CSV 导入后完成同一增量步骤。未升级的旧库，前台可使用版本资料包作只读回退，后台会提示先运行增量命令；HTTP 请求不执行建表或 ALTER TABLE。

本机修改前已对 15 张表备份并在独立临时库逐表还原核验，备份位于被忽略的 runtime/backups。正式库未重新初始化。
